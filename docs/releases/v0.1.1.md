# FrilAdd v0.1.1

FrilAdd v0.1.1 introduces **provider-independent Registry registration and resolution**. You can register a component Registry once and install individual items without passing the manifest URL on every command. FrilAdd remains a standalone Rust CLI and does not include or require FrilCraft.

## What's new

- **Project and global registries:** use `.friladd.json` in a consumer project or an OS-appropriate user configuration directory. Global registration can be reused across projects.
- **Registry management commands:** `friladd registry add`, `list`, `default`, and `remove`, with explicit `--global` support.
- **Short component installs:** `friladd add <item>` uses the configured default registry; `friladd add <registry>/<item>` selects an explicit registered alias.
- **Deterministic selection:** project configuration takes precedence over global configuration for matching aliases; a project default takes precedence over a global default. An explicit `--registry` option continues to work with an alias, local manifest path, or HTTPS URL.
- **Configuration safety:** validate config schemas and aliases, write configuration atomically, reject configuration symlinks and malformed files, and preserve existing destination-file protections.
- **Compatibility fixes:** retain bare local filenames such as `--registry registry.json`, and make `registry list --global` work independently of broken project configuration files.

## Getting started

From a React or other consumer project, first register your preferred provider:

```bash
npx friladd@0.1.1 registry add my-ui https://example.com/registry.json --global --default
npx friladd@0.1.1 registry list --global
npx friladd@0.1.1 list
npx friladd@0.1.1 add my-component --dry-run
npx friladd@0.1.1 add my-component
```

You can also select a named registry directly:

```bash
npx friladd@0.1.1 add my-ui/my-component
```

Replace the example Registry URL and item name with those of an actual compatible provider. FrilAdd ships with **no mandatory or hardcoded provider**.

An existing explicit Registry command remains supported:

```bash
npx friladd@0.1.1 add my-component --registry ./registry.json
```

## Compatibility and security

This release retains Registry Manifest v1 and the existing SHA-256 verification, path validation, dry-run, and no-overwrite installation behavior. It does not automatically install package dependencies or execute downloaded source code.

It also does not implement import-based `sync` or automatic registry discovery. Those are separate future enhancements.

## Distribution

The npm package uses the Rust executable and supports macOS ARM64/x64, Linux x64, and Windows x64. The release pipeline performs Rust tests, builds each native target, and runs packed npm consumer smoke tests on each supported platform.

See the [README](https://github.com/FrilLab/friladd#readme) for configuration rules and complete CLI usage.
