# FrilAdd v0.2.1 release candidate

**Release status: NO-GO.** Publication is gated on [release qualification #43](https://github.com/FrilLab/friladd/issues/43).

## Installation behavior changes

In v0.2.0, `fril add` tracked new files automatically. In v0.2.1, it copies selected source and declared file dependencies by default. A successful copy in a clean project leaves only the declared files and their directories. Pass `--managed` to track new files for status, update, remove, and exact restore. Both modes use the same validation, verified acquisition, and recoverable filesystem transaction.

Existing v0.2.0 lockfiles and registry configuration continue to work. A repeat add for an unchanged managed item preserves its ownership. Existing unmanaged destinations cause a conflict in either mode, even when they contain identical bytes. Package requirements remain advisory. The npm package is `friladd`, with both `fril` and `friladd` commands.

## Public registries

Zero-configuration discovery uses the curated HTTPS directory. Community operations require explicit consent on each invocation, including for transitive dependencies and lock-based restore. Custom registries keep their independent selection and transport. Future provider changes use reviewed directory data.
