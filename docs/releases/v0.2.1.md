# FrilAdd v0.2.1 candidate release notes

**Status: NO-GO — candidate only; not published.** This file describes a prepared compatibility patch candidate. It is not evidence of publication, provider admission, or production qualification.

## Candidate changes

- Adds curated public directory discovery and qualified zero-configuration install resolution.
- Keeps private and custom registry resolution and existing Registry v1/v2, config, lock, transaction, CLI alias, output, and exit status contracts compatible.
- Requires explicit `--trust-community REGISTRY_ID` on every community add/update/restore operation, including transitive providers. Lock v1 records provenance only and cannot grant trust.
- Reserves the official namespace through generic FrilLab repository identity rules, so adding future providers does not require CLI catalog changes.
- Uses restricted bounded HTTPS transport for the fixed directory, reviewed manifests, artifacts, and public dependencies.

## Known qualification blocker

The intended canonical directory is `https://registry.frillab.com/registries.json`, but DNS, Cloudflare hosting, TLS, and its JSON response are not verified. The directory has no active entries. The FrilCraft candidate in [frilregistry PR #1](https://github.com/FrilLab/frilregistry/pull/1) remains suspended under existing branch protections; the single-maintainer policy proposal is not adopted. Thus `fril search envelope` and `fril add frilcraft/envelope-reveal` cannot be qualified against an active official provider. This candidate must not be published until canonical hosting, an authorized reviewed provider, all other #43 gates, and exact-version release authorization are resolved.

FrilAssets and FrilRemotion real-resource integrations remain separate in [issue #33](https://github.com/FrilLab/friladd/issues/33) and are not claimed complete.
