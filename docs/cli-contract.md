# FrilAdd CLI contract

## Implemented commands

The commands in this section are implemented in the source tree. Published npm releases have their own versioned behavior. `fril` is the primary command; `friladd` remains a backward-compatible alias. Cargo installs expose both native executable names from the same CLI implementation. The npm package installs both command shims and includes one native executable per supported platform. The shims pass an explicit command identity to the selected executable: `fril --version` prints `fril VERSION`, while `friladd --version` preserves `friladd VERSION`; help usage follows the invoked command name. Help examples and diagnostics recommend `fril` for either invocation. For the npm package, append the arguments to `npm exec -- fril` or `npm exec -- friladd`.

| Command | Scope, defaults and output |
| --- | --- |
| `fril --help`, `fril help [COMMAND …]`, `fril COMMAND … --help` | Print usage on stdout. Registry subcommands accept help independently. Short form is `-h`. |
| `fril --version` | Print `fril VERSION` on stdout. Short form is `-V`. The `friladd` alias prints `friladd VERSION` for compatibility. |
| `fril registry add ALIAS SOURCE [--default] [--project DIRECTORY \| --global]` | Validate the manifest, then register the alias in the chosen scope and print confirmation. Duplicate aliases fail in that scope. `--default` sets the same scope's default. Content files are neither downloaded nor installed. |
| `fril registry list [--project DIRECTORY \| --global] [--json]` | Print tab-separated alias, source, scope, and an optional `default` field. The default view prints project aliases followed by unshadowed global aliases, sorted by alias within each group. `--global` lists only global entries. Both views are offline. An empty view succeeds with empty output; JSON uses `data.registries`. Remote credential/query/fragment parts are redacted. |
| `fril registry default ALIAS [--project DIRECTORY \| --global]` | Set an existing same-scope alias as default and print confirmation. Unknown aliases fail. No network request. |
| `fril registry remove ALIAS [--project DIRECTORY \| --global]` | Remove an existing same-scope alias and clear the default if it pointed to that alias. Print confirmation. Unknown aliases fail. No network request and no installed files are removed. |
| `fril registry discover [REGISTRY] [--json]` | Read the canonical static public directory only. It never registers aliases, fetches provider manifests or artifacts, or writes state. It reports entry status and reviewed provenance, including suspended entries when explicitly discovered. Directory errors fail the command. |
| `fril registry verify [ALIAS] [--registry ALIAS_OR_SOURCE] [--project DIRECTORY] [--json]` | Resolve a registry and stream each distinct declared source through bounded temporary staging while checking SHA-256 and, for v2, exact size. V1 retains its 10 MiB per-file limit; v2 allows 100 MiB per file and caps one verification operation at 512 MiB. Print a summary with registry name, manifest digest, item count and declared file count. Empty manifests succeed. Alias and `--registry` are mutually exclusive. No consumer project writes. |
| `fril list [ALIAS] [--registry ALIAS_OR_SOURCE] [--all-registries \| --public] [--project DIRECTORY] [--json]` | Read one configured manifest and print registry name and item names/descriptions in ascending item-name order. Alias and `--registry` are mutually exclusive. `--all-registries` reads up to 64 configured effective aliases with project shadowing. `--public` reads active official and community entries. With no configured default or selector, list reads active official entries. A selected directory or manifest failure fails without partial output. No artifact fetch. JSON sorts by provider then item ID. |
| `fril search QUERY [--registry ALIAS_OR_SOURCE] [--all-registries \| --public] [--project DIRECTORY] [--json]` | Search case-insensitively across item ID, name, description, tags, and kind. Empty queries are errors; no matches succeeds with an empty list. Multi-registry search uses configured effective aliases only. `--public` searches active official and community directory entries. With no configured default or selector, search uses active official entries. Directory and selected manifest failures fail the whole operation. Results sort by provider then item ID. Reads manifests only and never fetches artifact files. |
| `fril info ITEM_OR_REGISTRY/ITEM [--registry ALIAS_OR_SOURCE] [--project DIRECTORY] [--json]` | Show one selected manifest item, including provider and manifest identity, description, version, kind, license, paths and hashes, plus v2 sizes, tags, dependencies, and package requirements when present. A qualified unconfigured provider ID resolves from an active curated public entry. Registry v1 metadata it does not define stays absent. Reads the manifest only and never fetches files. |
| `fril doctor [--project DIRECTORY] [--json] [--online]` | Diagnose project path, config/lock validity, default registry resolution, transaction recovery state, owned file safety and drift, and package manager lockfiles. Offline by default; it never fetches manifests, repairs files, runs scripts, or writes state. Missing defaults and ordinary drift are warnings (exit 0); unsafe paths, invalid state, interrupted transactions, or failed requested online checks are failures (exit 2 with the report). `--online` validates manifests for up to 64 effective configured aliases with bounded manifest requests; it does not fetch assets. The current lock schema does not persist npm package requirements, reported as skipped. |
| `fril add ITEM [--registry ALIAS_OR_SOURCE] [--trust-community REGISTRY_ID] [--project DIRECTORY] [--dry-run] [--json]` | Select a case-sensitive item name or `ALIAS/ITEM`, resolve one manifest snapshot per canonical registry identity, and resolve the complete Registry v2 dependency DAG. Qualified IDs try configured aliases first and then the active public directory; official entries need no consent and community entries require exact first-use `--trust-community ID` consent. Every dependency uses the same public trust check. The dependency-first plan detects cycles, missing or ambiguous providers/items, exact version/digest conflicts, package conflicts, and target collisions before writes. It then streams and verifies all new files into bounded temporary staging and commits the entire graph and ownership lock through the recoverable transaction engine. V1 files are limited to 10 MiB; v2 files are limited to 100 MiB each and one graph operation to 512 MiB. Exact installed dependency items are reused; other versions require explicit update. Existing unmanaged files and files owned by another item are conflicts. Modified or missing managed files are preserved and cause an error with status/restore guidance. Dry run verifies the same content and transaction preconditions without project writes. JSON mode reports topologically ordered graph items, dependency edges, per-file ownership effects, package requirements, and advisory npm/pnpm/yarn commands. Package managers and provider scripts are never executed; FrilAdd never edits `package.json`. V2 target mappings are applied and persisted. |
| `fril installed [--project DIRECTORY] [--json]` | List lock records offline in provider/item order. Show provider identity, exact v2 version or v1 manifest digest, and file count. A missing lock is an empty successful result; a corrupt lock fails. Never reads or contacts registries. |
| `fril status [ITEM_OR_REGISTRY/ITEM] [--project DIRECTORY] [--json] [--check]` | Inspect only recorded targets offline. Report unchanged, modified, missing, unsafe, or unreadable files. An explicit unknown selector reports unmanaged; no selector never scans the project tree. Drift succeeds by default; `--check` emits the report and exits 2 if any state is not unchanged. Selectors accept item IDs, `provider-id/item-id`, or a configured registry alias and item ID. Duplicate unqualified IDs are an error. |
| `fril update ITEM --registry ALIAS_OR_SOURCE [--trust-community REGISTRY_ID] [--version EXACT_V2_VERSION] [--allow-downgrade] [--project DIRECTORY] [--dry-run] [--json]` | Require an explicit candidate manifest for custom registries. For a public-owned item, refresh from its current active public entry and preserve publisher/repository identity; community refresh requires exact consent unless this project already records the same registry and publisher. Refuse provider changes, modified/missing owned files, unmanaged targets, or dependency versions/digests pinned by installed items outside the candidate graph. Plan the candidate root and its complete v2 dependency graph, then verify and reconcile all graph additions, replacements, and obsolete root files through one transaction. Registry v2 version checks are exact; a downgrade requires `--allow-downgrade`. JSON reports mutation actions plus the resolved dependency graph and package requirements. |
| `fril remove ITEM [--project DIRECTORY] [--dry-run] [--json]` | Remove one lock-owned item offline. Delete only unchanged files, report already-missing files, and remove ownership in the same transaction. Refuse modified, unsafe or unreadable targets and items still required by another lock item. Dependencies that become unreferenced are retained by default and can be removed explicitly. |
| `fril restore [ITEM] [--project DIRECTORY] [--dry-run] [--json]` | Restore selected or all missing owned files from their exact locked locators, digests and sizes. Selecting an item includes its transitive dependency closure from the lock. Unchanged files are no-ops. Refuse modified, unsafe or unreadable targets and fail before writes if any source cannot be verified. Restore is registry-independent and uses the exact locked snapshots. |

## Public installation behavior

Public directory listing and discovery are implemented in the source tree. The canonical static endpoint is live but currently contains no active entries; the CLI fails closed if network access or directory validation fails. The static directory schema and trust boundary are defined in [public-registry.md](public-registry.md) and [schema v1](schemas/public-directory-v1.schema.json).

| Command | Contract |
| --- | --- |
| `fril info REGISTRY/ITEM`, `fril add REGISTRY/ITEM [--trust-community REGISTRY_ID]` | Prefer an explicit local alias if configured; otherwise resolve an active public entry. Never silently bypass a configured identity collision. No implicit provider choice for unqualified install. Official active entries need no prompt. Community installation requires the exact `--trust-community REGISTRY_ID` opt-in unless this project lock already records consent for the same registry ID and publisher. The lock stores immutable reviewed revision and manifest digest for reproducibility. Generic `--yes` is not approval; dry run never persists trust. Apply the same trust rule to dependencies. |

The public catalog is currently empty. Once an active official entry is admitted, ordinary list/search with no configured default will use official entries. Public selection requires the strict public transport and trust checks; explicitly selected custom/private registries retain their existing independent behavior. Offline lifecycle commands and locked exact restore never consult the directory.

Exit status **0** means success, including help and version. Invalid usage and operational failures use **2**. Operational errors are written to stderr with an `Error:` prefix. A human-mode command may have printed progress or its plan before an error. CLI parsing errors include usage and go to stderr. Scripts should branch on exit status and use machine mode where available.

### Paths and precedence

- The project root defaults to the invocation directory. An explicit `--project` is relative to that directory unless absolute. FrilAdd reads exactly that root's `.friladd.json` and never walks upward to find one. Installation requires an existing root directory. Configuration commands can inspect a missing final project directory with an existing parent, and registration can create that directory.
- Registration, default selection, and removal default to project scope. `--global` selects the platform configuration directory, overridable by `FRILADD_CONFIG_DIR`. Global-only commands work without reading project configuration. `--global` and `--project` cannot be combined.
- With `--registry`, a bare alias-shaped value names an alias unless a filesystem entry with that exact name exists in the invocation directory. Use an explicit path such as `./registry.json` to remove ambiguity even when the file is absent. An explicit local path is relative to the invocation directory, independent of `--project`. An explicit path or URL bypasses configuration loading.
- A positional alias or qualified item resolves the project alias first, then global. Without a selector, use the project default, then the global default. Each default refers to an alias in its own file. A global default still uses its global source if the same alias exists in the project without a project default.
- Relative stored sources resolve from the directory containing their configuration. The CLI stores local project registrations relative to that directory when possible and stores local global registrations as absolute paths.
- Missing configuration means an empty scope. Corrupt or unsupported configuration and stale defaults fail when used. Configured selection reads both configurations. A missing default or missing item gives an error.

```sh
fril --version
fril registry verify --help
fril registry add local ./registry/registry.json --project ./fixtures/consumer-project --default
fril registry list --project ./fixtures/consumer-project
fril registry default local --project ./fixtures/consumer-project
fril registry verify local --project ./fixtures/consumer-project
fril list local --project ./fixtures/consumer-project
fril add local/envelope-reveal --project ./fixtures/consumer-project --dry-run
fril add envelope-reveal --registry ./registry/registry.json --project ./fixtures/consumer-project
fril registry remove local --project ./fixtures/consumer-project
fril registry list --global
```

## Implemented 0.2.0 commands and options

The commands in this section are implemented in the source tree. Published npm releases have their own versioned behavior. Native usage is `friladd`; for npm, append the same arguments to `npm exec -- friladd`.

| Example | Contract |
| --- | --- |
| `fril search envelope --registry local --project ./app --json` | Read manifest metadata and match item IDs, names, descriptions, tags, and kinds case-insensitively. Empty queries fail; empty results succeed. `--all-registries` searches effective configured aliases and conflicts with explicit registry selection. A registry failure fails the whole operation. |
| `fril info local/envelope-reveal --project ./app --json` | Resolve an item with add precedence and report manifest metadata only. V1 has no invented version, kind, dependencies, or file size. |
| `fril list local --json`, `fril list --all-registries --json` | Report manifest items in deterministic order. Multi-registry output includes effective aliases and fails all if a registry is unavailable. |
| `fril doctor --project ./app --json [--online]` | Emit stable coded diagnostics. Offline mode is read-only. Warnings alone exit 0; failed required checks exit 2 with the complete report. `--online` validates configured manifests but does not fetch artifacts. |
| `fril registry list --json`, `fril registry verify local --json` | Report configured aliases or a verified manifest summary in the versioned envelope. Registry sources redact credentials, queries, and fragments. |

Commands default to the current project root and human output. Mutation commands apply their plan when `--dry-run` is absent, without requiring interaction. Managed commands resolve qualified selectors against lock ownership and report ambiguous unqualified names. Missing managed items are errors except when explicitly queried for unmanaged status. Dry runs have the validation and acquisition scope of their corresponding operation. Read-only commands do not run package managers, scripts, or repair steps. On-demand sync is outside 0.2.0.

### Machine output v1

Where supported, `--json` writes one UTF-8 JSON object with a trailing newline to stdout. Human diagnostics go to stderr. Machine output contains no terminal color, progress lines, timestamps, or URL credentials. Use stable key names, normalized project-relative file paths, and deterministic ordering. Sort registries by scope and alias, item results by provider identity and item identifier, and file rows by normalized target. `list` and `search` use `data.items`; search also returns the query. `info` uses `data.item`. Catalog commands read manifests only, never fetch artifact files, and return the same versioned envelope. Multi-registry list/search fail all if one configured effective registry cannot be loaded; output is empty on failure. Search rejects an empty/whitespace query and succeeds with an empty array when there are no matches. `registry list` uses `data.registries`; `registry verify` includes the manifest digest and declared counts. Doctor uses stable `checks` entries with states `ok`, `warn`, `fail`, or `skip`, a state-count summary, and a report even when required checks fail. Add output includes `dryRun`, root `item`, dependency-first `items`, per-file `install` or `unchanged` actions with ownership before and after, and grouped package requirements with manager suggestions. Package suggestions are informational; FrilAdd does not run them or edit package manifests. `installed` uses `data.items` with `providerId`, `itemId`, `version`, `manifestSha256`, and `fileCount`. `status` uses `data.items` and state counts; each file includes `target`, `state`, `expectedSha256`, and `actualSha256` when readable. Lifecycle mutation output uses `data.items` with per-file actions and ownership effects. The [output v1 schema](schemas/output-v1.schema.json) defines these command payloads. Dependency output order is deterministic and topological.

```json
{"schemaVersion":1,"command":"registry verify","data":{"registry":"local-dev","manifestSha256":"0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef","itemCount":2,"fileCount":4}}
```

`schemaVersion` and `command` are required. The command string uses canonical subcommand names separated by one space. `data` is a command-specific object. Use `items` arrays for list, search and installed, `registries` for registry list, an `item` object for info, and `items` plus integrity summaries for status. Use `checks` for doctor, with stable codes and states `ok`, `warn`, `fail` and `skip`. Mutation data includes `dryRun` and a plan of per-file actions with ownership effects. Individual implementation issues specify fields and assert the actual payloads in subprocess tests. For a failure before a report can be generated, stdout is empty. Status with `--check` and doctor can emit a complete report and exit 2. Exit status remains authoritative.

## Version and platform policy

- The CLI and npm package use the same release version and keep compatible command behavior across 0.2.x. CLI help and documentation advertise only shipped subcommands.
- Registry v1 and [configuration v1](schemas/config-v1.schema.json) use independent `schemaVersion` numbers. Readers reject unknown schema versions and unknown structural fields. An older CLI needs no implicit migration. A new registry version must coexist with v1. See the [registry schema](schemas/registry-v1.schema.json).
- The project lock has its own version and migration policy, specified in the [lock contract](lock-and-recovery.md). A CLI or registry upgrade alone must not rewrite lock identity. Machine output also has an independent schema version. Compatible additions are optional fields. Incompatible changes require a new version.
- The CI platform matrix tests Linux x64 (GNU, Ubuntu 22.04), macOS arm64 and x64, and Windows x64 (MSVC). Node.js 22 and its bundled npm are CI-tested for the npm wrapper. The wrapper declares Node.js 18 or newer. The native CLI uses no Node runtime. Stable Rust runs the primary matrix. Rust 1.88 is the minimum supported version and has a locked test job.
