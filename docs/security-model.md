# Security model

FrilAdd treats registry bytes, configuration, future lockfiles, and existing project files as untrusted inputs. Selecting a registry delegates control of its declared source and installed content to that publisher. SHA-256 verifies bytes against a manifest. Verify the publisher and pin a reviewed commit or release for reproducibility.

## Paths and changes

- Files follow the Registry v1 portable ASCII relative path rules. Within a plan, the case-folded path of each file must be unique, no file can be a prefix of another target, and shared directory spelling must agree.
- Reserved target segments at any depth, ignoring ASCII case, are `.git`, `.hg`, `.svn`, `.jj`, `.friladd`, `.friladd.json`, `friladd.lock.json`, and segments beginning with `.friladd-`. These cover VCS metadata, project configuration, lock records, and staging or transaction state. Reject Windows device stems, traversal, absolute paths, alternate data streams, empty segments, and trailing dots. OS-rejected filename lengths produce operational errors.
- Use a non-symlink directory as the project root and configuration directory. Manifests and config files must be regular files. The CLI canonicalizes user-selected ancestors to support normal platform aliases. It rejects symlinks and non-directory ancestors on manifest-controlled source and destination paths beneath those roots. Use trusted local directories for the explicitly chosen registry, project, and global configuration. A local registry intentionally grants access to regular declared files under its manifest directory.
- The installer verifies source bytes before project writes and publishes each staged file using a no-overwrite operation. Existing destinations, even if they contain identical bytes, are conflicts. Dry runs perform planning and hash checks without creating project, config, lock, or cache state. A conflict can terminate planning before acquisition. Registration verifies manifest structure only. Verification reads source bytes with the installer checks and leaves consumer paths untouched.
- V1 uses a 1 MiB manifest cap, a 1 MiB configuration cap, at most 1,000 items and 256 files per item, and a 10 MiB limit per source. Install buffers selected distinct sources before writing. Verify handles one source at a time and counts each declaration. A source requested more than once in an operation is fetched once, and contradictory digests fail.
- The existing installer attempts rollback on errors. An external process can modify paths between observation and use, and the existing installer has no crash journal or managed ownership. Use a local filesystem that supports hard links and atomic replacement. The shared [ownership and recovery API](lock-and-recovery.md) is available for managed lifecycle integration. Lifecycle commands must then operate on owned, validated paths and refuse local edits.
- FrilAdd copies source and binary bytes. It does not run provider code, package scripts or package managers. Review installed code before building or executing it.

## HTTPS

Remote registries and sources require HTTPS with TLS certificate verification and no embedded user information. A request permits up to four followed redirects and rejects the fifth redirect response. Each redirect must keep the original hostname, scheme, and effective port. Artifact paths resolve against the final manifest location. Connections have a five-second connect timeout and a 30-second total timeout per request. An explicit registry can point at a private address or use the user's configured network proxy. Same-origin policy does not establish publisher trust or isolate networks.

Compatibility allows queries in explicit and registered URLs. Keep credentials out of these URLs because configuration stores the original locator. Download errors emit only the HTTPS origin and a reason or HTTP status. `registry list` redacts the path and suffix if a configured remote URL contains user information, a query, or a fragment. Future lock and JSON output must use safe provenance, with no credentials or transient authorization URLs.
