# FrilAdd repository instructions

- Read the release epic and the issue before starting. Branch from the latest main after prerequisites merge. Keep one scoped PR per issue and coordinate registry, lock, transaction, and output contracts before changing shared interfaces.
- Keep the CLI provider-independent. Providers supply manifests and files. Preserve Registry v1, existing argument forms, exit codes, and the separation between registry, project configuration, lock, and CLI versions.
- Use `fril` as the primary user-facing command and keep `friladd` as a supported alias. Preserve the `friladd` package/crate/repository names and `.friladd.json`, `friladd.lock.json`, and `.friladd` state names. The npm package remains `friladd`; document `npx friladd`, not `npx fril`.
- Resolve one manifest snapshot per operation. Reuse validation, acquisition, destination planning, and the installer. Use shared ownership and transaction APIs for lifecycle operations once they land. Keep explicit installs separate from deferred on-demand sync.
- Keep list/search/info metadata-only: validate one manifest per selected registry, never fetch artifact files, and keep cross-registry results limited to configured effective aliases with explicit failure reporting. Version machine output through the shared schema.
- Treat manifests, configs, lockfiles, and local filesystem state as untrusted. Keep I/O bounded, verify hashes before writing, and refuse unsafe paths and ownership conflicts. Keep dry runs and offline inspection read-only. Preserve user edits and avoid rendering, executing provider scripts, installing packages, or adding runtime integrations.
- Run `cargo fmt --all -- --check`, `cargo clippy --locked --all-targets --all-features -- -D warnings`, `cargo test --locked`, the MSRV tests, and `npm run test:package --prefix npm` when package behavior is affected. Verify the full supported CI matrix before calling a PR ready. Add isolated positive, negative, regression, and failure-recovery tests for changed behavior. Assert exit status, output streams, filesystem state, and lack of unintended writes.
- Update the CLI contract, applicable schemas and security model, README examples, help, and changelog together. In each PR, link the issue and include contract decisions, exact tests and results, and remaining limitations. Keep proposed behavior visibly separate from shipped behavior.
- Keep fixture bytes stable across platforms and outside the npm tarball. Never merge or publish a release without maintainer approval.
- Keep source distribution as the default and lifecycle ownership opt-in via `--managed`. Preserve v0.2.0 managed state and provider compatibility. Keep both modes on the shared validation and recoverable transaction pipeline.
- After successful v0.2.1 publication and public verification, FrilAdd is in maintenance mode. Allow critical bug, security, compatibility, and dependency vulnerability fixes, necessary documentation corrections, and release infrastructure maintenance. New commands, features, metadata requirements, runtime dependencies, automatic package installation or sync, framework or provider integrations, lifecycle expansion, architecture rewrites, and unrelated refactoring require a new explicit maintainer decision. Expand the catalog through reviewed registry data and provider repositories. Issue #3 stays deferred.
- Keep release preparation separate from publication. Verify the exact tagged commit, native artifact checksums, packed npm contents, and provider qualification evidence before publication; publishing npm packages or the final release requires explicit maintainer authorization.
- Keep public directory and provider transport policies separate. The only production directory bootstrap is `https://registry.frillab.com/registries.json`; never add it to the provider-resource host allowlist or add a GitHub raw fallback. Do not claim it is deployed until DNS, TLS, JSON headers/bytes, and clean packed-CLI discovery have been verified.
- Community add/update/restore requires explicit `--trust-community ID` for each operation and transitive dependency. Lockfile provenance never grants consumer consent; publisher, origin, revision, or digest changes require new consent. Keep official namespace validation generic so provider additions do not require CLI releases.
- Treat frilregistry admission-policy changes, branch-protection changes, provider activation, Cloudflare domain provisioning, and public release publication as separately authorized operations. Keep candidates suspended until the active policy permits and review evidence exists.
